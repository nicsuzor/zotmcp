# ZotMCP

MCP server for semantic search and literature review across a shared Zotero academic library.

## Features

- **Semantic Search** - Vector-based search across library items
- **Citation Retrieval** - Get properly formatted academic citations
- **Similar Items** - Find related works by similarity
- **Author Search** - Find all works by specific authors
- **7 Specialized Tools** - Search, retrieve, and analyze academic literature

## Available Tools

### Zotero Library Search Tools
1. **`search`** - Semantic search across YOUR Zotero library (primary tool)
2. **`get_item`** - Retrieve full text and metadata by Zotero key
3. **`get_similar_items`** - Find works similar to a given item
4. **`get_collection_info`** - Library statistics and metadata

### OpenAlex Discovery Tools
5. **`search_openalex_author`** - Discover papers by author from OpenAlex (240M+ papers, NOT your library)
6. **`search_papers`** - Search OpenAlex for new papers beyond your library
7. **`get_paper_citations`** - Get forward citations for a paper from OpenAlex
8. **`get_referenced_works`** - Get backward citations for a paper from OpenAlex

#### OpenAlex tool payloads (lean by default)

The four OpenAlex list-returning tools (`search_papers`, `get_paper_citations`, `get_referenced_works`, `search_openalex_author`) return a **lean projection** per result so that ~50-item responses stay well under the MCP tool-result token cap. Each item includes: `id`, `doi`, `title`, `publication_year`, `cited_by_count`, `authors` (display names only), `venue`, `is_oa`, `has_oa_pdf`, top-3 `topics`, `n_referenced_works`, and a 300-char `abstract_snippet` (500-char for `search_papers`).

To opt into heavy fields per result, pass `fields=[...]`. Accepted values: `"abstract"`, `"referenced_works"`, `"topics"`, `"primary_location"`, `"open_access"`. Note that opting into `referenced_works` or `abstract` on large result sets may exceed the MCP token cap — request only what you need.

For the full record on a specific paper, call `get_paper_details(paper_id)`. For the full reference list of a specific paper, call `get_referenced_works(paper_id)`.

## Architecture

ZotMCP is an MCP (Model Context Protocol) server that provides semantic search and literature review capabilities for a shared Zotero academic library.

- **Zotero Library**: `prosocial` group library
- **ChromaDB Collection**: `prosocial_zot`
- **Embedding Model**: Google gemini-embedding-001 (3072 dimensions)

The ChromaDB is created by the Buttermilk vectorization pipeline.

- Full text sourced from Zotero group first
- Where full text is not available, we extract full text from source PDF
- Each source is chunked using a semantic splitter into approximately 1000 tokens, with overlap of 250 tokens.
- Citations are generated by a LLM based on the first page of full text in the format: `Authors (Year). Title. Outlet`

## Search behaviour — important caveats

Empirically observed during dogfood (2026-05-20, `brain:zotmcp-22a4e78e`). These may be addressed by upstream fixes; treat as the current state, not a permanent property.

- **Embeddings are concept-literal, not strongly synonymic.** Despite the model being gemini-embedding-001 (3072-d), queries phrased in conceptual / framing vocabulary do **not** reliably retrieve items titled in doctrinal / domain vocabulary. Example: query `private corporate power knowledge infrastructure epistemic gatekeeper` did not surface Picker 2012, *Private Digital Libraries and Orphan Works* — even though these are synonyms to a human. The same item surfaced when the query literally contained "private digital library". Practical implication: **search with the terms the literature itself uses**, not with the conceptual frame you're writing in. If unsure, run two or three phrasings.
- **`n_results` is filtered by an undocumented score floor.** Requesting `n_results=15` often returns 3–5 items. The server drops results below a confidence threshold before honouring the cap. Broadening or rephrasing the query is more effective than increasing `n_results`.
- **Absolute scores are not calibrated.** Top semantic scores in legal / governance / philosophy queries top out around 0.4–0.6; there is no "0.9 = match" regime. Relative ordering within a result set is informative; absolute thresholds across queries are not.
- **Hybrid mode rescues fuzzy-title matches.** Hybrid (the default) reliably surfaces items that pure-semantic mode drops, via title-field fuzzy matching. Prefer hybrid unless you have a reason not to.
- **Response does not report `total_in_corpus` / `above_threshold` / `returned`.** A return of "4 items" cannot be distinguished from "library only has 4" vs "only 4 above threshold". This makes confidence-calibration of a small return difficult.

If you're triaging a body of literature where the doctrinal vocabulary differs from your writing vocabulary (a common case in interdisciplinary work), expect to do a **vocabulary-mapping pass** before relying on search hits.
